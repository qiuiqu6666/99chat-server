# 精聊后台管理 API — 前端对接说明

本文档描述 **PHP 管理端**（`admin-api`）当前已开放接口，供 **Vue** 或其它前端在浏览器中对接。

---

## 1. 基础信息

| 项目 | 说明 |
|------|------|
| 协议 | 生产环境建议使用 **HTTPS**（如 `https://admin.jingliaochat.com`） |
| 数据格式 | **JSON**，请求与响应均为 UTF-8 |
| 请求头 | `Content-Type: application/json`（POST JSON 时必填） |
| 鉴权 | 除登录与公开探测接口外，需携带 **`Authorization: Bearer <access_token>`** |

**Base URL 示例**（按实际部署替换）：

- 生产：`https://admin.jingliaochat.com`
- 本地直连 PHP：`http://127.0.0.1:9080`（仅调试）

所有路径均相对于域名根路径，例如完整登录地址为：`{Base URL}/api/v1/auth/login`。

---

## 2. 跨域 CORS

- 浏览器跨域请求时，服务端会校验请求头 **`Origin`**。
- **`Origin`** 必须出现在服务端环境变量 **`CORS_ORIGINS`** 的允许列表中（逗号分隔多个域名，需包含协议与端口，如 `https://admin.jingliaochat.com`）。
- 预检请求 **`OPTIONS`** 成功时返回 **204**，无响应体。
- 允许的方法：`GET, POST, PUT, PATCH, DELETE, OPTIONS`。
- 允许的请求头：`Content-Type, Authorization, X-Requested-With`。

若前端页面域名未加入 `CORS_ORIGINS`，浏览器控制台会出现 CORS 拦截，需在服务端 `.env` 中追加并重启 PHP 服务。

#### `GET /health`

健康检查（含数据库连通、表数量统计，以及 **IM 侧简要运营指标**）。

**响应 200 示例：**

```json
{
  "ok": true,
  "db": true,
  "current_database": "jingliaochat",
  "table_count": 75,
  "documented_table_count": 69,
  "expected_table_count": null,
  "schema_mismatch": false,
  "wallet_balance_total": "9433.65",
  "wallet_frozen_total": "12.00",
  "registered_today": 3,
  "online_users": 12,
  "login_today": 45
}
```

**说明：**

- `documented_table_count`：文档记载的 IM 侧基线表数量；`table_count` 为当前库实际 BASE TABLE 数量（含后台 `admin_*` 等）。
- 若配置了 `EXPECTED_TABLE_COUNT` 且与 `table_count` 不一致，则 `schema_mismatch` 为 `true`。
- **`wallet_balance_total`**：**`missu_user_wallet.balance`** 全库合计（**可用余额**汇总），字符串两位小数。
- **`wallet_frozen_total`**：**`missu_user_wallet.frozen_amount`** 全库合计（冻结金额），便于与「全站资金」对账。
- **`registered_today`**：当日 **`DATE(register_time) = CURDATE()`** 的新注册用户数（`missu_users`）。
- **`online_users`**：当前 **`is_online = 1`** 的用户数（与列表在线状态口径一致）。
- **`login_today`**：当日 **`DATE(latest_login_time) = CURDATE()`** 且 `latest_login_time` 非空的用户数（与仪表盘「今日登录」口径一致）。
- 「今日」均以 MySQL **会话时区**为准（见环境变量 **`DB_SESSION_TIMEZONE`**，如 `+08:00`）。

数据库不可用时可能返回 **503**，Body 含 `ok: false` 等字段（**不**含上述运营指标）。

### 3.2 认证

#### `POST /api/v1/auth/login`

管理员登录，成功后返回 **JWT**。

**请求 Body：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `username` | string | 是 | 登录名，≤64 字节（trim 后非空） |
| `password` | string | 是 | 密码，≤128 字节（trim 后非空） |

**请求示例：**

```json
{
  "username": "admin",
  "password": "your_password"
}
```

**响应 200 示例：**

```json
{
  "access_token": "<JWT 字符串>",
  "token_type": "Bearer",
  "expires_in": 86400,
  "user": {
    "id": 1,
    "username": "admin",
    "display_name": "系统管理员",
    "role": "super_admin",
    "permissions": [
      "admin.manage",
      "dashboard.view",
      "group.read",
      "group.write",
      "system.config",
      "user.read",
      "user.write",
      "wallet.read"
    ]
  }
}
```

**说明：**

- `expires_in`：秒，与服务端 `JWT_TTL_SECONDS` 一致（默认 86400）。
- `permissions`：当前角色在后台 RBAC 中的权限码列表，可用于控制菜单与按钮显示；**与 JWT 载荷中权限一致**。

**常见错误 Body：**

| HTTP | `error` | 说明 |
|------|---------|------|
| 422 | `validation_error` | 缺少或非法的 `username` / `password` |
| 401 | `invalid_credentials` | 用户名或密码错误（对外统一文案） |
| 403 | `account_locked` | 账户锁定，附带 `locked_until`（时间由服务端写入） |
| 403 | `account_disabled` | 账号被停用 |
| 500 | `server_misconfigured` | 服务端 JWT 等配置异常 |

#### `GET /api/v1/admin/login-logs`

分页查询 **后台管理员登录流水**（表 **`admin_login_logs`**；含成功与失败尝试）。**需登录**，权限 **`admin.manage`**（默认仅超级管理员角色持有）。

与 **IM 用户**设备登录 **`GET /api/v1/users/login-logs`**（`missu_user_device_history`）数据源不同，勿混淆。

**Query：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `page` / `page_size` | int | 默认 `page=1`，`page_size=50`，最大 100 |
| `sort` | string | 默认 `login_at_desc`；允许 `login_at_asc`、`id_asc`、`id_desc` |
| `admin_user_id` | string | 可选，管理员主键（数字字符串，与 `admin_users.id` 一致） |
| `username` | string | 可选，对 `username_attempted` **模糊**匹配，≤64 字节 |
| `success` | string | 可选，`1` 成功 / `0` 失败 |
| `ip` | string | 可选，精确匹配来源 IP，≤45 字节 |
| `login_at_from` / `login_at_to` | string | 可选，日期 **`YYYY-MM-DD`**（含当日起止，与 IM 登录日志 Query 习惯一致） |

**响应 200：** `source`（固定 `admin_login_logs`）、`items`、`total`、分页字段。每行含 `id`、`admin_user_id`、`username_attempted`、`success`、`ip`、`geo_address`、`user_agent`、`fail_reason`、`login_at`，以及 LEFT JOIN 的 `admin_username`、`admin_display_name`（无绑定用户时可为 `null`）。

**422** 若 `login_at_from` / `login_at_to` 格式非法。**403** 无 `admin.manage`。

---

#### `GET /api/v1/admin/audit-logs`

分页查询 **后台操作审计**（表 **`admin_audit_logs`**；由写操作如改密、调账等写入）。**需登录**，权限 **`admin.manage`**。

**Query：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `page` / `page_size` | int | 默认 `page=1`，`page_size=50`，最大 100 |
| `sort` | string | 默认 `created_at_desc`；允许 `created_at_asc`、`id_asc`、`id_desc` |
| `admin_user_id` | string | 可选，操作者 `admin_users.id`（数字字符串） |
| `action` | string | 可选，精确匹配动作码（如 `user.login_password.reset`），≤128 字节 |
| `resource_type` | string | 可选，≤64 字节 |
| `resource_id` | string | 可选，≤128 字节 |
| `created_from` / `created_to` | string | 可选，日期 **`YYYY-MM-DD`** |

**响应 200：** `source`（`admin_audit_logs`）、`items`、`total`、分页。每行含 `id`、`admin_user_id`、`action`、`resource_type`、`resource_id`、**`detail`**（由 `detail_json` 解析的对象，解析失败则为 `null`）、`ip`、`geo_address`、`created_at`、`admin_username`、`admin_display_name`。

**422** 日期非法。**403** 无 `admin.manage`。

```http
GET /api/v1/admin/login-logs?page=1&success=1
Authorization: Bearer <access_token>
```

```http
GET /api/v1/admin/audit-logs?page=1&action=user.wallet.balance_adjust
Authorization: Bearer <access_token>
```

### 3.3 仪表盘统计

#### `GET /api/v1/dashboard/overview`

返回 IM 侧汇总指标（**需登录**，且 JWT 含权限 **`dashboard.view`**）。

**请求头：**

```
Authorization: Bearer <access_token>
```

**响应 200 示例：**

```json
{
  "stats": {
    "user_total": 1234,
    "registered_today": 5,
    "login_today": 89,
    "group_total": 42,
    "online_users": 128,
    "wallet_balance_total": "9433.65",
    "wallet_frozen_total": "12.00"
  },
  "labels": {
    "user_total": "用户总数",
    "registered_today": "今日注册",
    "login_today": "今日登录",
    "group_total": "群组数量",
    "online_users": "当前在线用户数",
    "wallet_balance_total": "全站可用余额合计",
    "wallet_frozen_total": "全站冻结金额合计"
  }
}
```

**字段说明：**

| 字段 | 数据来源 | 说明 |
|------|----------|------|
| `user_total` | `missu_users` | 用户总行数 |
| `registered_today` | `missu_users.register_time` | `DATE(register_time) = CURDATE()`（MySQL 会话时区下的「今天」） |
| `login_today` | `missu_users.latest_login_time` | 今日有登录成功记录的用户数（`latest_login_time` 非空且日期为今天） |
| `group_total` | `group_base` | 未删除的群（`g_status <> -1`，含正常与封禁） |
| **`online_users`** | `missu_users` | 当前 **`is_online = 1`** 的用户数；与 **`GET /health`** 同名字段口径一致，**始终随 `stats` 下发（整型，可为 `0`）**，便于仪表盘与探测接口对齐。 |
| **`wallet_balance_total`** | `missu_user_wallet` | 全库 **`balance`** 合计（可用余额汇总），**字符串两位小数**；与 **`GET /health`** 同名字段一致。 |
| **`wallet_frozen_total`** | `missu_user_wallet` | 全库 **`frozen_amount`** 合计，**字符串两位小数**；与 **`GET /health`** 同名字段一致。 |

**常见错误：**

| HTTP | `error` | 说明 |
|------|---------|------|
| 401 | `unauthorized` / `invalid_token` | 未登录或 Token 无效 |
| 403 | `forbidden` | 无 `dashboard.view` 权限 |

#### `GET /api/v1/dashboard/daily-metrics`

按 **自然日**（MySQL 会话时区 **`CURDATE()`**）返回最近若干天的 **趋势序列**，供图表使用（**需 `dashboard.view`**）。

**Query：**

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `days` | int | `30` | 天数，**1～366**；含 **今天** 共 `days` 个日历日（例如 `30` 表示从今天往回共 30 天） |

**响应 200：**  

- `days`、`start_date`、`end_date`：本次范围（`start_date`…`end_date` 闭区间）。  
- **`online_users`**：当前 **`missu_users.is_online = 1`** 用户数（**请求时刻快照**，与 **`GET /health`**、**`GET /api/v1/dashboard/overview`** 的 `stats.online_users` 口径一致；**始终为整型**）。  
- **`items`**：按日期 **升序**；每项：  
  - **`date`**：`YYYY-MM-DD`  
  - **`registered_count`**：`missu_users` 当日 `DATE(register_time)` 计数  
  - **`login_distinct_users`**：`missu_user_device_history` 当日 **`COUNT(DISTINCT user_uid)`**（有设备登录的用户数；与 `overview.login_today` 所用 `latest_login_time` **口径不同**，更适合历史趋势）  
  - **`groups_created_count`**：`group_base` 当日 `DATE(create_time)` 新建群数（含日后被删除的群，仅按创建时间统计）  
- **`labels` / `hints`**：字段中文说明与口径提示。

```http
GET /api/v1/dashboard/daily-metrics?days=30
Authorization: Bearer <access_token>
```

### 3.4 用户列表（分页查询）

#### `GET /api/v1/users`

IM **`missu_users` 分页列表**（**需登录**，权限 **`user.read`**）。

**请求头：** `Authorization: Bearer <access_token>`

**Query 参数：**

| 参数 | 类型 | 默认 | 说明 |
|------|------|------|------|
| `page` | int | `1` | 页码，≥1 |
| `page_size` | int | `20` | 每条页数，1～100 |
| `keyword` | string | — | 可选；模糊匹配 `nickname`、`user_mail`、`phone_num`、`user_uid`（转为字符串匹配） |
| `status` | string | — | 可选；`0` 仅禁用，`1` 仅正常；不传则不过滤 |
| `is_online` | string | — | 可选；`1` 仅 `missu_users.is_online = 1`（在线）；`0` 仅非在线（`NULL` 或 `0`）；**不传则不在线状态上过滤** |
| `sort` | string | `register_time_desc` | 见下表 |

**`sort` 允许值（其它值按 `register_time_desc`）：**

| 值 | 排序 |
|----|------|
| `register_time_desc` / `register_time_asc` | 按注册时间 |
| `latest_login_time_desc` / `latest_login_time_asc` | 按最近登录时间（NULL 会排在升序前 / 降序后，取决于 MySQL） |
| `user_uid_desc` / `user_uid_asc` | 按 UID |

      "user_status": 1,
      "is_online": 1,
      "user_avatar_file_name": "400069_xxx.jpg",
      "what_s_up": null,
      "user_desc": null,
      "user_type": 0,
      "user_regieon": null,
      "device_type": 1,
      "termination_time": null,
      "nickname_last_modified_time": null,
      "nickname_last_modified_time2": 0,

**本接口返回的字段（已排除敏感列）：**  
`missu_users`：`user_uid, user_mail, nickname, user_sex, phone_num, register_ip, register_time, latest_login_time, latest_login_ip, user_status, is_online, user_avatar_file_name, what_s_up, user_desc, user_type, user_regieon, device_type, termination_time, nickname_last_modified_time, nickname_last_modified_time2`  

**钱包（`missu_user_wallet` LEFT JOIN，无记录则为 `null`）：**  
- `wallet_balance`：可用余额（字符串小数，与库中 `decimal` 一致）  
- `wallet_frozen_amount`：冻结金额  

**关系统计（子查询，整型）：**  
- **`friend_count`**：`missu_roster` 中 `user_uid` 为该用户的行数（好友数）  
- **`group_count`**：该用户在 `group_members` 中的记录数，且对应 **`group_base.g_status <> -1`**（未删除群；与运营上「当前有效群」口径一致）  

不下发 `fund_password` 等资金敏感字段。

**故意不下发的列：** `user_psw`、验证码/推送/令牌类（`verification_*`、`http_token`、`ios_device_token`、`voip_device_token`、`getui_cid`）、`clear_all_before_time2` 等。汇总详情见 **`GET /api/v1/users/detail`**。

**前端你还要做的：**

| 事项 | 说明 |
|------|------|
| 头像 URL | `user_avatar_file_name` 仅为文件名；需与 **Java `base_conf` / 静态资源域名** 拼完整 URL（与 App 客户端规则一致）。 |
| 时间展示 | `register_time` / `latest_login_time` 等为数据库会话时区下时间，前端可按「北京时间」直接显示或转本地时区。 |
| `user_status` | `1` 正常、`0` 禁用；列表可过滤、标签展示。 |
| `user_sex` | `1` 男、`0` 女。 |
| 大表性能 | 用户量极大时，`keyword` 模糊查询可能较慢；后续可在 MySQL 对常用检索列加索引或接入 ES（现为先满足后台列表）。 |

**常见错误：**

| HTTP | `error` | 说明 |
|------|---------|------|
| 401 | `unauthorized` / `invalid_token` | 未登录或 Token 无效 |
| 403 | `forbidden` | 无 `user.read` 权限 |

**请求示例：**

```http
GET /api/v1/users?page=1&page_size=20&keyword=test&status=1&is_online=1&sort=register_time_desc
Authorization: Bearer <access_token>
```

#### `GET /api/v1/users/detail`

**单用户详情页**专用聚合接口（**需 `user.read`**）。**Query：** `user_uid`（必填）。

**响应 200** 结构：

| 字段 | 说明 |
|------|------|
| `profile` | 与列表一致的安全用户字段 + `wallet_balance` / `wallet_frozen_amount`（nullable 字符串）+ `friend_count` / `group_count` |
| `groups` | `total`、`limit`（80）、`truncated`、`items`（未删除群，按 `join_time` 倒序，结构同 **`/api/v1/users/groups`** 单行） |
| `friends` | `total`、`limit`（150）、`truncated`、`items`（好友行，字段同 **`/api/v1/users/friends`**） |
| `accounts_same_ip` | `shared_ips`（该用户设备历史上出现过的合法 IP）、`total`、`limit`（40）、`truncated`、**`items`**（**其他**账号摘要，字段与 **`/api/v1/users/related-by-ip`** 一致：`user_uid`、`nickname`、`user_mail`、`phone_num`、`user_status`、`latest_login_time`、`latest_login_ip`、`register_ip`、`device_type`；不含本人）。当 **无任何可用登录 IP**（`shared_ips` 为空）时下发 **`hint`: `no_login_ip_in_history`**，便于前端提示。 |

#### `GET /api/v1/users/login-logs`

| 参数 | 类型 | 说明 |

| `page` / `page_size` | int | 默认 `page=1`，`page_size=30`，最大 100 |

### 3.5 用户维护：登录密码 / 资金密码 / 钱包余额调账 / **禁用或允许登录** / **解冻 IM 登录试错冻结**

以下接口均为 **POST JSON**，**需登录**，权限 **`user.write`**。成功执行后均会向 **`admin_audit_logs`** 写入一条审计（`detail_json` 中 **不包含** 明文密码）。其中 **解冻 IM 登录试错** 不调 MySQL **`missu_users`**（仅清 Java **`LoginAttemptManager`** 内存）；**禁用登录**则只改库的 **`user_status` /（可选）`http_token`**。

**通用请求头：** `Authorization: Bearer <access_token>`、`Content-Type: application/json`

#### `POST /api/v1/users/login-disabled`

设置 IM 账号 **是否允许登录**：更新 **`missu_users.user_status`**。Java **`MyControllerJSON.authrizationLogin`** 在校验手机号验证码与密码时均要求 **`user_status = 1`**，设为 **`0`** 后 **密码登录与手机短信验证码登录** 均无法通过认证。

**Body：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `user_uid` | int | 是 | IM 用户 `missu_users.user_uid` |
| `disabled` | boolean | 是 | `true`：禁止登录 → `user_status = 0`；`false`：允许登录 → `user_status = 1`。也接受 `"1"`/`"0"`、`1`/`0` |
| `clear_http_token` | boolean | 否 | 为 `true` 且本次为禁用时，同时将 **`http_token` 置为 `NULL`**。未传时：**禁用默认 `true`，解禁默认 `false`** |

**响应 200 示例：** `{ "ok": true, "user_uid": 400069, "disabled": true, "user_status": 0, "http_token_cleared": true }`

**审计 `action`：** `user.login_disabled.set`（含 `user_status_before` / `user_status_after`、`http_token_cleared`）

**常见错误：** `422`：`disabled` 非合法布尔 / 缺字段；`404`：`user_not_found`。

说明：若该账号曾为注销态（例如 Java 写入的 **`user_status = -2`**）， **`disabled:false`** 会将其 **`user_status` 设为 `1`**，相当于运营侧恢复登录能力，请谨慎操作。

#### `POST /api/v1/users/wallet/balance-adjust`

在 **`missu_user_wallet`** 上 **增加或减少可用余额**（`balance`），并在 **`missu_wallet_transactions`** 插入一条成功流水（`status=1`）。**扣减**时要求 **可用余额** `balance - frozen_amount ≥ amount`（与 Java `WalletManager` 一致）。依赖 PHP **`bcmath`** 扩展。

**Body：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `user_uid` | int | 是 | IM 用户 UID |
| `direction` | string | 是 | `add` 增加，`subtract` 减少 |

**流水类型：** 调增使用 **`transaction_type = 1`**（与充值/入账类一致），调减使用 **`transaction_type = 2`**（与提现等出账类一致）。`amount` 字段始终为正，与表 CHECK `amount > 0` 一致。

**响应 200 示例：**

```json
{
  "ok": true,
  "user_uid": 400069,
  "direction": "add",
  "amount": "100.00",
  "balance_before": "9412.65",
  "balance_after": "9512.65",
  "transaction_no": "adm1730..."
}
```

**审计 `action`：** `user.wallet.balance_adjust`（含 `direction`、`amount`、`balance_before`、`balance_after`、`transaction_no`、`remark`）

**常见错误（补充）：**

| HTTP | `error` | 说明 |
|------|---------|------|
| 403 | `forbidden` | 无 `user.write` |
| 404 | `user_not_found` | `user_uid` 不存在 |
| 422 | `validation_error` 等 | 参数非法（资金密码非 6 位、金额格式、`direction` 非法等） |
| 422 | `insufficient_available_balance` | 调减时可用余额不足 |
| 409 | `concurrent_wallet_update` | 乐观锁冲突（`version` 不匹配），可重试 |
| 500 | `bcmath_required` | 服务端未安装 `bcmath` |

#### `POST /api/v1/users/login-unfreeze`

代理调用 **Java** 特权接口 **1014-31-12**（`IMAdminProcessor` → `LoginAttemptManager.unfreeze`），清除该登录键在 **Java 服务端内存** 中的「连续输错密码冻结」状态（与 `RainbowChatServer/unfreeze_login.py` 等价）。**需**在部署环境配置 **`.env`**：`IM_REST_POST_URL`、`IM_ADMIN_REST_TOKEN`（与 Java `TOKEN_FOR_HTTP_VERIFY_ENABLED` 策略一致：`false` 时可用纯数字 UID 作为 token）。

PHP 发往 Java 的出站 IP须落在 Java **`ADMIN_LEGAL_REMOTE_IP`** 允许范围内（或与 Java **同机**调用 `127.0.0.1`）。

**Body（二选一，不可都缺）：**

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `user_uid` | int | 否 | IM 数字 UID；与 `login_key` 传 `400069` 等价 |
| `login_key` | string | 否 | Java 侧冻结键：**UID 字符串**或**邮箱**（与用户登录输入一致，≤128 字节）。若 UID 与邮箱曾分别触发冻结需分别解冻 |

**响应 200：** `{ "ok": true, "login_key": "400069" }`（`login_key` 为本次提交用于解冻的键）

**审计 `action`：** `user.im_login_unfreeze`

**常见错误：**

| HTTP | `error` | 说明 |
|------|---------|------|
| 503 | `im_rest_not_configured` | 未配置 `IM_REST_POST_URL` |
| 503 | `im_admin_token_not_configured` | 未配置 `IM_ADMIN_REST_TOKEN` |
| 422 | `user_uid_or_login_key_required` | body 缺少 `user_uid` 与 `login_key` |
| 502 | `im_upstream_unreachable` | 无法连接 Java / 超时 |
| 502 | `im_invalid_response` | Java 返回非 JSON |
| 502 | `im_unfreeze_failed` | Java 返回 `success` 非 true 或 `returnValue` 非 `"1"`（如客户端 IP 未授权、`INVALID_TOKEN` 等）；响应体内可能含 `hint` |

#### 3.8.1 `msg_type` 与 `msg_content` 格式（后台列表 / 审计展示）

接口返回的 **`msg_type`**、**`msg_content`** 与 IM 客户端、Java 服务端约定一致（字段名在 HTTP JSON 中仍为 **`msg_type`** / **`msg_content`**，与库表 **`missu_user_msgs_collect`** / 读扩散表一致）。后台做摘要、搜索高亮或类型标签时，按下表解析即可。

**`msg_type` 一览（与 `com.evaserver.chat.im.dto.MsgType` 对齐）**

| 值 | 含义 | `msg_content`（`m`）常见形态 |
|----|------|------------------------------|
| **0** | 文本 | 纯文本字符串 |
| **1** | 图片 | 多为 **32 位 MD5 文件名**（无扩展名）；新版可为 **JSON 字符串**：`{"f":"<md5>","w":1920,"h":1080}`，`f` 为主图名 |
| **2** | 语音 | 语音文件名字符串 |
| **3** | 送礼（发出） | 礼品标识 |
| **4** | 送礼（索取） | 礼品标识 |
| **5** | 文件 | 常见 **`fileName|fileMd5|fileLength`** 竖线分隔 |
| **6** | 短视频 | 常见 **`fileName|fileMd5`** |
| **7** | 名片 | 按产品解析（个人/群） |
| **8** | 位置 | 位置描述或结构化约定字符串 |
| **9** | **音视频通话记录** | **JSON 对象**（见下表） |
| **10** | 红包 | JSON（含 `packet_id` 等），详参钱包专题文档 |
| **11** | 转账 | JSON，详参钱包专题文档 |
| **90** | 系统提示 | 提示文案或结构化内容；发送方 UID 常 **`0`** |
| **91** | 撤回 | 按 `fp` / `parent_fp` 等关联原消息，展示「已撤回」类文案 |

**`msg_type = 9`（通话记录）— `msg_content` 为 JSON 字符串**

解析后字段：

| 字段 | 类型 | 说明 |
|------|------|------|
| `voipType` | int | **`0`**：语音通话；**`1`**：视频通话 |
| `recordType` | int | **`0`**：已取消；**`1`**：对方已拒绝；**`2`**：对方无应答；**`3`**：已接通 |
| `duration` | int | 通话时长（**秒**）；**仅当 `recordType === 3` 时有意义** |

示例（已接通 17 秒的视频通话）：

```json
{"duration":17,"recordType":3,"voipType":1}
```

后台展示建议：`recordType !== 3` 时显示状态文案（如「对方已拒绝视频通话」）；`recordType === 3` 时将 `duration` 格式化为 `mm:ss` 或 `hh:mm:ss`。

**兼容**：若缺少 `voipType`，部分历史数据可能含 **`type`**：`"voice"` / `"video"`，可映射到 0/1。

**`msg_content` 嵌套（SyncKey / 漫游与后台拉数均可遇到）**

部分历史或同步路径下，**`msg_content` 本身可能是 JSON 字符串**，内层仍含 `ty`、`m` 等；解析建议：**先对 `msg_content` 做 `JSON.parse` 尝试**——若得到对象且含 **`m`** 字段，则**真实展示内容取 `m`**，**类型以对象内 `ty` 或外层 `msg_type` 为准**（与现网数据一致时）；解析失败则把整段 **`msg_content` 当作原文**（文本消息等）。

**延伸阅读（仓库内 IM 专题，非 admin-api 路径）**

- 聊天页总表与图片 `m` 约定：`RainbowChatServer_extracted/聊天页面_完整对接文档.md` §7、§7.1  
- 通话气泡 UI：`RainbowChatServer/RainbowChatServer/音视频通话消息-聊天对话页前端对接文档.md`

- 上传下载与文件类展示：`RainbowChatServer_extracted/前端对接文档_OSS文件上传下载.md`

## 5. 前端实现建议（Vue）

### 5.1 存储 Token

- 内存 / **`sessionStorage`**：降低 XSS 窃取后长期滥用的风险（按团队安全策略二选一）。
- **勿**把 Token 塞进 Cookie 且同时暴露给未做防护的第三方脚本。

登录成功后保存 `access_token`，并在后续请求的 `Authorization` 头中携带。

### 5.2 Axios 示例

```javascript
import axios from 'axios';

const api = axios.create({
  baseURL: import.meta.env.VITE_ADMIN_API_BASE || 'https://admin.jingliaochat.com',
  timeout: 30000,
  headers: { 'Content-Type': 'application/json' },
});

api.interceptors.request.use((config) => {
  const token = sessionStorage.getItem('admin_access_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

api.interceptors.response.use(
  (res) => res,
  (err) => {
    if (err.response?.status === 401) {
      // 清 token、跳登录页
    }
    return Promise.reject(err);
  }
);

export async function login(username, password) {
  const { data } = await api.post('/api/v1/auth/login', { username, password });
  sessionStorage.setItem('admin_access_token', data.access_token);
  return data;
}

export const fetchMe = () => api.get('/api/v1/auth/me');
```

### 5.3 fetch 示例（登录）

```javascript
const base = 'https://admin.jingliaochat.com';
const res = await fetch(`${base}/api/v1/auth/login`, {
  method: 'POST',
  headers: { 'Content-Type': 'application/json' },
  body: JSON.stringify({ username: 'admin', password: '***' }),
});
const data = await res.json();
if (!res.ok) throw new Error(data.error || res.statusText);
```
