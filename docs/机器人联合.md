# 万人大群代理反水查询与仅本人可见报表发送方案交接文档

## 1. 业务目标

本方案针对单群几千至上万人、多级代理关系的业务场景。

核心使用方式：

```text
代理用户进入群
→ 后端判断该用户在当前群是否拥有代理权限
→ 有权限则显示“查反水”“历史记录”
→ 点击“查反水”
→ 后端统计该代理本人及全部下级代理、全部下级玩家的最新汇总
→ 生成仅当前请求人可见的群内业务消息
→ 其他群成员不可见
```

历史查询：

```text
点击“历史记录”
→ 选择日期或日期范围
→ 后端查询当天或多天历史
→ 生成 TXT 或 CSV 文件
→ 文件发送到当前群
→ 仅当前请求人可见
```

适用指标：

```text
流水
玩家输赢
平台输赢
已反水
待反水
余额
上分
下分
盈亏
代理人数
玩家人数
```

# 2. 权限规则

## 2.1 可见范围

代理只能查看：

```text
自己
+
自己名下全部直属下级
+
全部间接下级
+
下级代理
+
下级普通玩家
```

不能查看：

```text
自己的上级
兄弟代理
其他代理分支
其他群数据
```

## 2.2 任意代理层级使用同一套规则

不按一级、二级、三级分别写死权限。

统一判断：

```text
目标人员是否属于当前代理的下级关系树
```

示例：

```text
代理A
├─ 代理B
│  ├─ 玩家C
│  └─ 代理D
│     └─ 玩家E
└─ 玩家F
```

代理A可查看：

```text
A、B、C、D、E、F
```

代理B可查看：

```text
B、C、D、E
```

代理D可查看：

```text
D、E
```

代理B不能查看：

```text
A、F
```

## 2.3 普通玩家

普通玩家：

```text
不显示“查反水”
不显示“历史记录”
调用接口返回403
```

## 2.4 群隔离

所有权限判断和数据查询必须包含：

```text
playerGroupId
```

唯一业务身份：

```text
playerGroupId + wxid
```

# 3. 用户操作流程

## 3.1 进入群

IM 前端进入群后调用：

```http
GET /api/im/groups/{groupId}/agent/permission
```

后端处理：

```text
1. 获取当前登录IM用户
2. 根据IM用户和groupId查绑定wxid
3. 查询该wxid在当前群的玩家数据
4. 判断是否有效代理
5. 返回按钮权限
```

代理返回：

```json
{
  "success": true,
  "isAgent": true,
  "permissions": {
    "queryCurrentRebate": true,
    "queryHistory": true,
    "exportTxt": true,
    "exportCsv": true
  }
}
```

普通玩家返回：

```json
{
  "success": true,
  "isAgent": false,
  "permissions": {
    "queryCurrentRebate": false,
    "queryHistory": false,
    "exportTxt": false,
    "exportCsv": false
  }
}
```

前端处理：

```text
isAgent=true
→ 显示“查反水”“历史记录”

isAgent=false
→ 完全隐藏
```

---

## 3.2 点击“查反水”

前端调用：

```http
POST /api/im/groups/{groupId}/agent/rebate/current
```

请求体：

```json
{
  "displayMode": "SUMMARY"
}
```

后端处理：

```text
1. 获取当前登录用户
2. 获取当前群绑定wxid
3. 校验当前用户是代理
4. 获取当前代理本人及全部下级范围
5. 读取当前最新玩家快照
6. 汇总当前流水、输赢、已反水、待反水等
7. 生成仅本人可见业务消息
8. 发送到当前群
9. 返回发送成功
```

---

## 3.3 点击“历史记录”

前端弹出：

```text
今天
昨天
近7天
近30天
自定义日期
自定义日期范围
```

用户选择：

```text
单天
或
多天
```

文件格式：

```text
TXT
CSV
```

前端调用：

```http
POST /api/im/groups/{groupId}/agent/rebate/history/export
```

请求示例：

```json
{
  "startDate": "2026-07-01",
  "endDate": "2026-07-07",
  "fileType": "CSV",
  "includeDetail": true
}
```

后端处理：

```text
1. 校验登录用户
2. 校验当前群绑定关系
3. 校验代理权限
4. 查询历史日期范围
5. 按当天代理关系确定可见范围
6. 查询每日历史汇总
7. 生成TXT或CSV
8. 将文件上传到IM文件服务
9. 向当前群发送仅本人可见文件消息
10. 记录导出审计日志
```

# 5. 当前汇总计算规则

## 5.1 统计范围

```text
当前代理本人
+
全部下级代理
+
全部下级玩家
```

手动托：

```text
playerType=1
```

默认不参与真人业务汇总。

## 5.2 流水

```text
总流水 = 可见范围内所有真人玩家 totalFlow 之和
```

## 5.3 玩家输赢

```text
玩家总输赢 = 可见范围内 totalProfitLoss 之和
```

## 5.4 平台输赢

```text
平台总输赢 = -玩家总输赢
```

## 5.5 已反水

```text
已反水 = 可见范围内 totalRebate 之和
```

## 5.6 待反水

```text
待反水 = 可见范围内 pendingRebate 之和
```

当前快照没有 `pendingRebate` 时，可按：

```text
remainingFlow × rebateRate ÷ 10000
```

实时计算。

## 5.7 代理待结算流水 / 待结算反水（仅机器人同步）

字段：

```text
agentPendingFlow
agentPendingRebate
```

由机器人同步到玩家快照 / 日归档。

- 团队汇总 `summary` / 历史 / 导出：仍用 `totalRebated`、`pendingRebate`（范围内合计），**不含** `agentPending*`。
- 个人反水汇总框 `personal`（`GET /me/agent/rebate/current`）：
  - `pendingRebate = floor(本人 remainingFlow × rebateRate ÷ 10000)`（后端计算）
  - `agentPendingFlow` / `agentPendingRebate` = 机器人同步到该代理快照的值（结清后应为 0）
  - `totalPendingRebate` / `totalRebate1` = `pendingRebate + agentPendingRebate`（同值）
  - 级差公式由机器人侧按直属下级可结算流水与比例差计算并同步；App 不对下级 `remainingFlow` 重算（否则代理已领级差后仍会残留待领取）

## 5.8 （已合并到 5.7）

原「预计总反水 / 代理差额反水」团队口径已废弃。团队侧用 `totalRebated` / `pendingRebate`；个人侧见 `personal` 框。

## 7.1 单天历史


## 7.2 多天历史

例如选择：

```text
2026-07-01 ～ 2026-07-07
```

生成：

```text
每天一行汇总
+
日期范围总计
```

## 7.3 历史关系

历史查询必须按当天代理关系统计。

示例：

```text
7月1日 玩家C属于代理B
7月2日 玩家C转到代理D
```

则：

```text
代理B可看到C在7月1日的数据
代理B不能看到C在7月2日之后的数据
```

# 11. IM 仅本人可见消息模型

## 11.1 消息可见性字段

IM 消息表或消息扩展字段增加：

```text
visibility_type
```

枚举：

```text
ALL
REQUESTER_ONLY
USER_LIST
```

当前业务使用：

```text
REQUESTER_ONLY
```

## 11.2 消息表建议字段

```sql
ALTER TABLE im_message
ADD COLUMN visibility_type VARCHAR(30) NOT NULL DEFAULT 'ALL',
ADD COLUMN requester_user_id BIGINT NULL,
ADD COLUMN business_type VARCHAR(50) NULL,
ADD COLUMN business_id VARCHAR(100) NULL;
```

索引：

```sql
CREATE INDEX idx_im_message_visibility
ON im_message (
    conversation_id,
    visibility_type,
    requester_user_id,
    created_at
);
```

## 11.3 拉取消息时过滤

群消息查询必须增加：

```sql
WHERE
    visibility_type = 'ALL'
    OR (
        visibility_type = 'REQUESTER_ONLY'
        AND requester_user_id = :currentUserId
    )
```

其他用户不能通过：

```text
消息列表
消息详情
搜索
转发
附件下载
历史同步
```

看到该消息。

## 11.4 文件权限

附件下载接口必须再次校验：

```text
当前用户ID = requester_user_id
```

不能只依靠前端隐藏。

## 11.5 推送

WebSocket 推送时：

```text
仅推送给请求人的连接
```

不能广播给整个群后再让前端隐藏。

# 20. 当前查询 SQL

```sql
SELECT
    SUM(p.balance) AS total_balance,
    SUM(p.total_flow) AS total_flow,
    SUM(p.total_up) AS total_up,
    SUM(p.total_down) AS total_down,
    SUM(p.total_profit_loss) AS player_profit_loss,
    -SUM(p.total_profit_loss) AS platform_profit_loss,
    SUM(p.total_rebate) AS total_rebated,
    SUM(p.pending_rebate) AS pending_rebate,
    SUM(CASE WHEN p.is_agent = 1 AND r.distance >= 1 THEN 1 ELSE 0 END) AS agent_count,
    SUM(CASE WHEN p.is_agent = 0 AND r.distance >= 1 THEN 1 ELSE 0 END) AS player_count
FROM robot_player_relation r
JOIN robot_player_snapshot p
  ON p.player_group_id = r.player_group_id
 AND p.wxid = r.descendant_wxid
WHERE r.player_group_id = :groupId
  AND r.ancestor_wxid = :currentAgentWxid
  AND p.active = 1
  AND p.player_type <> '1';
```
