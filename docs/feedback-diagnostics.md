# 意见反馈附带聊天排查记录

## 接口

扩展现有 `POST /feedback`（用户登录，multipart/form-data），保留 type、content、clientVersion、screenshots：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| diagnostics | 可选文件 | UTF-8 文本，最多 2 MiB，必须以 `Chat recovery report v1\n` 开头。不接收压缩包或任意应用日志。 |
| diagnosticsConsent | 布尔 | 带文件时必须为 true。前端默认不勾选，用户选择后随反馈发送。 |

原响应数据增加 `diagnosticsAttached: true/false`；沿用全局 `{code:0,data:{...}}` 包装。前端兼容裸响应；勾选附件后必须收到 true 才视为日志上传成功。旧服务器忽略附件时会明确提示反馈已提交、日志未保存。

错误：400 `DIAGNOSTICS_CONSENT_REQUIRED` / `INVALID_DIAGNOSTICS`；413 `DIAGNOSTICS_TOO_LARGE`。旧客户端不带新增字段仍可提交。

新增 `GET /api/v1/feedback/{id}/diagnostics`：后台管理员登录且具有 `user.read` 权限，返回 UTF-8 txt 下载、`Cache-Control: no-store`，无附件返回 404。普通用户和匿名请求不能下载。后台可根据反馈编号调用此接口，使用现有管理员 Authorization，不是公开下载链接。本轮未修改后台管理网页的操作按钮。

## 保存与范围

附件存入服务端数据库独立表 `feedback_diagnostics`，与 `user_feedback` 使用相同 SQL 事务，保存失败回滚反馈记录。外键绑定反馈编号，删除反馈时级联删除日志。查询反馈列表不读取附件正文。原截图仍走已有图片存储。

上传的是现有 ChatRecoveryDiagnostics 导出的近期聊天恢复记录，包括时间、会话和消息编号、错误类型、应用版本及消息落库诊断快照；不是完整设备日志，也不收集聊天正文。已有文件轮转限制继续有效。服务器按不可信附件保存，只作为文本下载，不执行、不生成公开 URL，也不写入服务运行日志。

反馈提交沿用原有请求行为，无新增自动重试；若连接中断导致提交结果不明，手动重新提交仍可能产生另一条反馈。本轮未新增反馈幂等协议或自动日志过期清理。

## 发布

### 发布版精简接口诊断

前端统一 ApiClient 安装 ApiFailureInterceptor，不受 kDebugMode 控制。记录 HTTP 4xx/5xx、超时/网络错误和根对象业务错误码；忽略成功请求及主动取消。仅保留 UTC 时间、方法、白名单化路由、HTTP 状态、安全业务码、耗时、响应 request/trace ID（存在且格式合法时）及同类次数，不保存查询参数、动态路径值、请求/响应正文、Authorization 或异常原始字符串。

同类错误一分钟最多写入一次，全局每分钟最多写入 20 条；内存最多 100 组，写队列最多 100 条。磁盘两个 64 KiB 文件轮转，常规写入延迟 30 秒合批，失败重试间隔一分钟。导出时尽力刷新，文件不可用时保留内存结果；强杀进程可能丢失尚未落盘的最后一批。重复次数为当前进程聚合，已保存样本和当前聚合可能重叠，不能直接相加。日志不发起额外网络请求，只随用户选中的反馈附件上传。现有后端接口和建表脚本无需再增加字段。

范围仅为经过统一 ApiClient 的请求，不包括腾讯 IM SDK 内部网络或其他独立网络客户端。发布版路径不依赖断言/调试开关；本轮通过 47 项相关 Flutter 测试，未构建或实机验证发布包。

1. 在反馈所在数据库执行 `scripts/migrate-feedback-diagnostics.sql`。
2. 发布后端，再发布前端。检查网关及 Spring multipart 总大小上限允许原截图加 2 MiB 日志。
3. 使用测试账号提交带日志/不带日志的反馈，再用有权限和无权限的后台账号验证下载。

构建配置已阻止旧 bootstrap 包覆盖新反馈实现。仓库完整构建仍受之前缺失 bootstrap JAR 和既有源码编译错误限制。本轮进行了定向实际源码编译、H2/JPA 保存/回滚测试及权限校验，尚未部署、未做线上上传。前端反馈及诊断相关 16 项测试通过，后端 4 项测试通过。
